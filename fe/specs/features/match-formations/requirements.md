## 목표·사용자 이야기

- 운영진은 경기 참석 선수로 `1쿼터` 등 제목을 붙인 포메이션을 작성하고 저장한다.
- 팀원은 해당 경기의 제목별 배치와 후보를 모바일·데스크톱에서 확인한다.
- 일반 팀원에게 편집 기능을 노출하지 않으며, 운영진은 최대 10개 한도와 저장 상태를 이해할 수 있다.
- 운영진은 자체 경기의 참석 선수를 홈·어웨이로 먼저 나누고 해당 편의 선수로 포메이션을 작성한다.
- 제품 스펙의 F-01~F-09, 세부 정책, 제외 범위를 그대로 따른다. D-01은 참가자 편 배정 기능을 포함하는 것으로 확정했다.

## 경로·탐색

| 경로 | 접근 | 목적 |
| --- | --- | --- |
| `/match/[matchId]` | 활성 팀원 | 기존 상세에 `포메이션 보기` 진입점 추가 |
| `/match/[matchId]/formations` | 활성 팀원 | 제목 선택, 배치·후보 조회 |
| `/match/[matchId]/formations/new` | 운영진 | 새 포메이션 작성 |
| `/match/[matchId]/formations/[formationId]/edit` | 운영진 | 포메이션 수정 |
| `/match/[matchId]/formations/sides` | 운영진, 자체 경기 | 참가자 편 배정 관리 |

- 목록 상단에 경기 일시·상대/자체 경기 정보와 `경기 상세` 복귀 링크를 둔다. 별도의 팀 탭·전역 헤더 링크는 추가하지 않는다.
- 첫 진입 시 생성 순서의 첫 포메이션을 선택한다. 나머지는 제목·홈/어웨이·프리셋이 보이는 선택 목록으로 전환한다. 최대 10개 제목을 고정된 한 줄에 억지로 넣지 않는다.
- 생성/수정 성공 후 목록으로 돌아가 저장한 포메이션을 선택한다. 목록 URL의 `formationId` 쿼리로 선택을 유지한다. 쿼리 대상이 삭제되었거나 목록에 없으면 첫 항목으로 돌아가고 안내한다. 다른 경기의 내용을 가져오지 않는다.
- 삭제 성공 후 다음 항목, 없으면 이전 항목, 전체 0개면 빈 상태로 전환한다.
- 현재 `page-access.ts`는 경기 상세 하위 경로를 모두 운영진으로 판정한다. **조회 경로만 정확히 팀원 접근으로 추가**하고 새 작성·수정·편 배정 및 기존 `/record`는 운영진으로 유지해야 한다. 접두어 전체를 팀원 접근으로 풀지 않는다. 외부 경기의 `/formations/sides` 접근은 공통 404다.

## 자체 경기 편 배정

- 경기 상세의 참여 현황에 선수별 `미배정`/`홈`/`어웨이`를 표시하고 운영진에게 `편 배정 관리` 링크를 제공한다. 외부 경기에는 이 UI를 추가하지 않는다.
- 포메이션 목록 상단에는 모든 팀원이 볼 수 있는 `편 배정` 요약과 펼쳐 볼 수 있는 참석 명단을 제공한다. `미배정 3명 · 홈 12명 · 어웨이 11명`처럼 표시하고 포메이션이 없어도 보인다.
- 운영진 관리 화면은 참석 선수만 이름순으로 표시하며 각 선수의 편을 `미배정`/`홈`/`어웨이` 중 선택한다. PC·모바일 모두 선수 이름과 편 컨트롤을 함께 확인할 수 있는 행 목록으로 구성한다. 드래그나 자동 팀 나누기는 추가하지 않는다.
- 관리 화면에 `편 배정은 이 경기의 모든 포메이션에 적용돼요.`를 표시한다. 기존 데이터가 홈으로 저장되어 있을 수 있으므로 `기존 경기의 참가자는 홈으로 배정되어 있을 수 있어요. 배정을 확인해 주세요.`도 보조 안내로 제공한다.
- 저장은 `편 배정 저장`으로 명시적으로 실행하며, 변경이 없으면 비활성화한다. 참석 선수가 없어도 조회는 가능하고 `참석 투표한 선수가 없어요.`를 표시한다.
- 편별 인원은 제한하지 않는다. 일부 선수를 미배정으로 남겨 저장할 수 있다. 불참·제거된 선수는 현재 편 배정 목록에서 제외한다.
- 저장 전 `편 배정을 바꾸면 기존 포메이션의 일부 배치가 제외될 수 있어요.`를 안내하고 확인/취소를 제공한다. 확인 후 변경된 선수만 PATCH하며, 취소 시 작성 내용은 유지한다.
- 성공 시 `편 배정을 저장했어요.`를 표시하고 포메이션 목록으로 돌아가 전체 명단·배치 상태를 갱신한다. 포메이션 초안에서 관리 화면으로 이동할 때는 기존 이탈 확인을 적용한다.
- 일반 팀원은 읽기만 가능하며 관리 URL 접근은 404다. 취소 경기는 편 조회만 제공하고 저장을 막는다.
- 버전 충돌·참석 자격 변경·통신 실패 시 입력을 유지하고 최신 명단 확인/재시도를 제공한다. 자동으로 덮어쓰거나 불참 선수를 다시 참석 처리하지 않는다.

## 조회 화면

- 경기장: 골키퍼 아래, 공격 방향 위. 카탈로그의 고정 위치에만 표시한다. 자체 경기 홈·어웨이도 같은 방향을 사용한다.
- 제목, 프리셋, 자체 경기의 홈·어웨이, `배치 8/11명`, `후보 5명`을 표시한다. 유효하지 않은 배치는 배치 인원에서 제외한다.
- 빈 위치는 포지션 이름과 빈 자리 표현을 사용한다. 조회 화면의 빈 위치는 편집 컨트롤로 보이지 않게 한다.
- 선수 이름은 현재 팀 표시 이름을 사용한다. 동명이인은 선택 목록에서 `팀원 #ID`로 구분하고, 긴 이름은 상세 표시를 열어 전체 이름을 읽을 수 있게 한다.
- 후보는 서버의 `attendingPlayers` 중 현재 포메이션과 같은 편에서 유효 배치를 제외한 명단이다. 미배정·반대편 선수는 후보에 넣지 않는다. 미배정 인원은 후보와 별도 요약에 표시한다.
- 참석 자격을 잃거나 편이 달라진 배치는 이름과 `배치 제외`를 함께 표시한다. `편 미배정`/`다른 편으로 변경`도 사유로 구분한다. 운영진에게 `참석 명단 또는 편 배정이 바뀌었어요. 제외된 선수의 배치를 수정해 주세요.`를 안내하고 일반 팀원에게도 변경 상태를 숨기지 않는다.
- 데이터는 진입·포메이션 선택·저장 후 새로 불러오며 `새로고침`도 제공한다. 실시간 반영이라고 표현하지 않는다.

## 작성·수정 흐름

1. 제목 → 자체 경기의 홈/어웨이 → 프리셋 순서로 입력한다. 외부 경기는 홈/어웨이 선택을 숨긴다. 자체 경기는 선택한 편의 선수만 제공하고 미배정 선수가 있으면 `편을 배정하면 선수를 선택할 수 있어요.`와 관리 링크를 제공한다.
2. 고정 위치를 선택하면 배치 가능한 참석 선수 선택 목록을 연다. 현재 다른 위치에 배치된 선수는 위치를 함께 표시한다.
3. 선수 선택 시 빈 위치 배치, 후보와 기존 선수 교체, 두 위치 선수 교환을 구분해 처리한다. 배치된 위치에는 `배치 해제`도 제공한다.
4. PC에서는 후보 → 위치, 위치 → 위치 드래그를 지원하되 고정 위치에서만 놓을 수 있다. 범위 밖에 놓으면 원래 상태를 유지한다. 자유 좌표는 저장하지 않는다.
5. 배치가 있는 상태에서 프리셋 또는 홈/어웨이 변경 시 초기화 확인을 받는다. 취소하면 기존 값·배치가 유지된다. 편 변경 확인 시 선수 배치를 비우고 새 편 후보를 표시하며 제목·프리셋·참가자의 실제 편 배정은 유지한다.
6. `저장` 시 전체 배치를 한 번에 보낸다. 처리 중 중복 클릭을 막고 `저장 중…`으로 표시한다. 실패 시 제목·선택·배치를 유지한다.
7. `취소`·뒤로가기·화면 내 이동에서 미저장 변경이 있으면 이탈 확인을 제공한다. 새로고침/탭 닫기는 브라우저가 지원하는 범위에서 기본 이탈 경고를 사용한다.

조회 상태를 직접 편집 상태로 재사용해 다른 팀원에게 미저장 내용이 노출되면 안 된다. 자동 저장은 하지 않는다.

## 화면 상태·문구

| 상태 | 처리 |
| --- | --- |
| Loading | 권한·데이터 확인 전 이름·포메이션을 표시하지 않고 로딩 표시 |
| Empty | `아직 등록된 포메이션이 없어요.` 운영진이며 생성 가능할 때만 추가 버튼 |
| 참석 선수 0명 | `참석 투표한 선수가 없어요.` 빈 포메이션 저장은 허용 |
| 해당 편 선수 0명 | `이 편에 배정된 참석 선수가 없어요.` 운영진에게 편 배정 관리 링크. 빈 포메이션 저장은 허용 |
| 후보 0명 | `후보 선수가 없어요.` 로딩·실패와 구분 |
| 10개 도달 | 추가 비활성화, 경기당 최대 10개 안내. 자체 경기 양쪽 합계 사용 |
| 취소 경기 | 조회 유지, 생성·수정 숨김, 운영진 삭제만 허용 |
| 저장 완료 | `포메이션을 저장했어요.` 목록에서 저장한 항목 선택 |
| 삭제 확인 | `‘1쿼터’ 포메이션을 삭제할까요?` 홈/어웨이도 함께 표시 |
| 입력 오류 | 제목·프리셋·배치 오류를 해당 입력 가까이에 표시 |
| 참석 명단·편 변경 | 최신 명단을 다시 조회하고 유효하지 않은 배치를 표시, 입력 유지 |
| 동시 수정 충돌 | `다른 운영진이 수정했어요. 최신 내용을 확인해 주세요.` 초안 유지, 사용자가 선택한 경우에만 최신 내용으로 교체 |
| 네트워크·서버 오류 | 오류와 다시 시도 제공. 빈 포메이션으로 오인하게 하지 않음 |
| 접근 권한 상실·없는 리소스 | 본문/초안을 숨기고 공통 404. 쿠키 갱신을 한 번 시도한 401도 같은 화면 처리 |

POST 응답이 네트워크 오류로 유실된 경우 자동으로 생성 요청을 재전송하지 않는다. 기존 제목·입력은 유지하고 목록을 재조회해 저장 여부를 먼저 확인하도록 안내한다. 동명 제목이 가능하므로 제목만으로 저장 성공을 추정하지 않는다.

## 반응형·접근성

- 375px 모바일, 768px 태블릿, 1440px 데스크톱에서 주요 흐름을 확인하고 320px에서 화면 전체 가로 넘침이 없어야 한다.
- 모바일 후보는 경기장 아래, 넓은 화면에서는 오른쪽에 놓는다. 경기장 종횡비·위치 비율을 유지한다.
- 조회에는 선택 드롭다운/목록을 사용해 많은 제목이 화면을 밀어내지 않게 한다. 저장·취소는 폼 하단에서 일관되게 제공한다.
- 프리셋은 새 색상 팔레트·장식 배경 대신 기존 표면·선·브랜드 토큰으로 그린다. 그림 이미지에 선수 텍스트를 굽지 않는다.
- 위치는 편집 시 접근 가능한 버튼으로 구현하고 `골키퍼, 김민수, 선수 변경`처럼 이름과 동작을 읽을 수 있게 한다. 선수 선택·교환·해제·저장이 키보드만으로 가능해야 한다.
- 선수 선택창은 포커스 이동·Escape 닫기·원래 위치로 포커스 복귀를 제공한다. 모바일에서도 드래그가 필수 동작이면 안 된다.
- 색상만으로 홈·어웨이, 선택, 오류를 구별하지 않는다. 일반 컨트롤의 44px 터치 영역, 포커스 표시와 대비 기준을 따른다.

## API 연결

성공은 기존 `CommonResponse<T>`, 실패는 기존 `ErrorResponse` 형식을 사용한다. 상세 필드·에러 코드·자격 판정은 백엔드 계약이 단일 기준이다.

| 동작 | API |
| --- | --- |
| 목록·편집 초기화·명단 갱신 | `GET /matches/{matchId}/formations` |
| 새 작성 | `POST /matches/{matchId}/formations` |
| 전체 수정 | `PUT /matches/{matchId}/formations/{formationId}` |
| 삭제 | `DELETE /matches/{matchId}/formations/{formationId}?version={version}` |
| 편 배정 관리 초기화·갱신 | `GET /matches/{matchId}/participant-sides` |
| 변경한 선수의 편 저장 | `PATCH /matches/{matchId}/participant-sides` |

- 새 작성·수정 경로도 GET 목록에서 대상과 카탈로그를 읽는다. 수정 대상이 없으면 404이다.
- 생성·수정 성공 응답의 ID로 선택을 유지하며 목록을 재조회한다. HTTP 409를 일반 재시도로 덮어쓰지 않는다.
- 편 배정 PATCH는 조회 응답의 별도 `version`과 변경된 선수 목록을 보낸다. 생략한 선수는 유지하고 `UNASSIGNED`로 해제한다. 포메이션 버전과 혼용하지 않는다.
- 권한은 백엔드가 판단한다. 서버의 `permissions`는 UI 표시를 돕는 값이며 프론트 검사를 서버 인가 대신 사용하지 않는다.
- 기존 인증 쿠키·API helper를 사용하고 JWT·초안을 웹 스토리지에 새로 저장하지 않는다.

자동 테스트는 경로별 권한 분기와 배치/교환/후보 계산처럼 중요한 로직에만 간단히 작성한다. 나머지 화면·반응형은 수동 검증하고 구현 후 lint/build 및 필요한 기존 회귀 테스트를 실행한다. **현재 테스트를 실행하거나 기능을 구현한 상태가 아니다.**

## 기존 동작 보존·미해결 사항

- 기존 경기 투표·메모·기록·통계·팀 탭·404 처리를 유지한다. `AVAILABLE`와 실제 출석을 혼동하지 않는다.
- 프리셋 선택은 선수 참석 상태나 기존 참가자 `team_side`를 임의로 변경하지 않는다.
- D-01은 참가자 편 배정을 포함하는 것으로 반영했다. 현재 미해결 사용자 질문은 없으며 그 외 기본안은 검토용이다. 구현 중 임의로 범위를 확대하지 않는다.
