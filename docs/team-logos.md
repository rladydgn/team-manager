# 팀 로고

팀 등록 및 정보 수정에서 PNG/JPG 파일을 선택하고 미리본 뒤 저장합니다. 기존 팀 로고 교체·제거는 팀장과 부팀장만 할 수 있습니다. 저장 전 선택하거나 제거한 로고는 취소 시 반영되지 않습니다.

## 이미지 규격

- 권장 및 저장 크기: **256×256px**.
- 업로드 용량: **최대 1MB (1,048,576바이트)**.
- 입력 크기: 가로·세로 각각 64~2,048px, PNG/JPG만 허용.
- 서버에서 실제 이미지 형식을 검사하고 비율을 유지해 정사각형 투명 여백에 맞춥니다. 자르거나 늘려서 왜곡하지 않습니다. 원본 대신 재인코딩한 PNG만 보관합니다.
- 목록에서는 44~48px, 팀 홈에서는 48~64px, 선택 미리보기에서는 80px로 표시합니다. 미등록 또는 이미지 로드 실패 시 팀 이름 앞 두 글자를 표시합니다.

## 서버 영구 저장 폴더

`TEAM_LOGO_STORAGE_PATH` 환경변수로 저장 폴더를 설정합니다. 기본값은 백엔드 실행 위치 기준 `./uploads/team-logos`입니다.

운영 환경에서는 예를 들어 `/var/lib/team-manager/team-logos`처럼 배포 디렉터리 외부의 절대 경로를 지정하고, 백엔드 실행 계정에 읽기·쓰기 권한을 부여합니다. 컨테이너를 사용하면 이 경로에 영구 볼륨을 마운트해야 합니다. 서버가 여러 대라면 동일한 공유 저장 경로를 사용해야 합니다. DB와 함께 이 폴더를 백업합니다. 별도 DDL 변경은 없습니다.

파일은 무작위 UUID 이름으로 저장하고 `teams.logo_url`에는 `/teams/logos/{uuid}.png`를 기록합니다. 프론트의 API 기본 주소를 붙여 조회하므로 파일 경로를 외부에 노출하지 않습니다. 로고는 공개 팀 소개에 쓰이므로 비로그인 상태에서도 조회할 수 있습니다. 새 파일마다 URL이 바뀌어 로고 교체 시 캐시된 이전 이미지가 표시되지 않습니다.

DB 저장이 롤백되면 신규 파일도 삭제합니다. 정상 저장 후 교체·제거된 이전 파일은 팀 변경 이력 참조를 위해 보관합니다. 오래된 파일 정리가 필요하면 현재 팀 데이터와 변경 이력에서 참조하는 URL을 확인한 후 별도 보관 정책을 적용합니다.

## API

- 기존 JSON 팀 등록·수정 API를 유지합니다.
- 파일이 있으면 `POST /teams` 또는 `PUT /teams/{teamId}`에 `multipart/form-data`를 보냅니다. `request` 파트는 기존 팀 요청의 JSON(`application/json`), `logo` 파트는 이미지입니다.
- 로고 제거는 기존 수정 API에서 `logoUrl`을 비워 저장합니다. 파일 업로드가 있으면 업로드한 로고로 교체합니다.
- `GET /teams/logos/{fileName}`은 PNG 응답이며 디렉터리 목록과 임의 파일 경로는 제공하지 않습니다.
- 파일 크기는 서버 multipart 설정과 이미지 검증에서 모두 제한합니다. 프록시가 있으면 1MB 파일과 multipart 부가 데이터를 전달할 수 있도록 전체 요청 제한을 2MB 이상으로 설정합니다.
