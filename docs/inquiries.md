# 비공개 서비스 문의

## 범위와 이용 흐름

- 로그인한 사용자가 서비스 운영자에게 보내는 문의다. 팀에 소속되지 않은 사용자도 작성할 수 있다.
- 상단 사용자 메뉴의 **문의하기**, **내 문의** 또는 가이드 하단에서 접근한다.
- `/inquiries/new`: 카테고리·제목·내용 입력 → 등록 → 문의 상세로 이동.
- `/inquiries`: 본인의 문의만 최신순으로 표시한다. 등록일, 카테고리, 제목, 상태와 20개 단위 페이지 이동을 제공한다.
- `/inquiries/[inquiryId]`: 본인이 작성한 문의의 전체 내용과 상태를 확인한다.

## 입력과 상태

| 구분 | 값 |
| --- | --- |
| 카테고리 | 사용 문의 (`USAGE`), 오류 제보 (`BUG`), 기능 제안 (`SUGGESTION`), 기타 (`OTHER`) |
| 제목 | 필수, 입력 길이 100자 이내, 공백만 입력 불가 |
| 내용 | 필수, 입력 길이 10,000자 이내, 공백만 입력 불가 |
| 상태 | 답변 대기 (`WAITING`), 답변 완료 (`ANSWERED`) |

길이는 프런트엔드와 Kotlin의 UTF-16 문자열 길이를 기준으로 검사하며 저장 시 앞뒤 공백을 제거한다. 새 문의 상태는 서버가 `WAITING`으로 지정한다. 제목과 내용은 일반 텍스트로 표시한다.

## API와 접근 제어

| 메서드 | 경로 | 동작 |
| --- | --- | --- |
| POST | `/inquiries` | `{ category, title, content }`로 등록, 201 반환 |
| GET | `/inquiries?page=0` | 본인 문의 요약 목록과 `page`, `pageSize`, `hasNext` 반환 |
| GET | `/inquiries/{inquiryId}` | 본인 문의 상세 반환 |

모든 API는 기존 HttpOnly 인증 쿠키를 사용한다. 작성자 ID는 검증된 요청 속성에서 가져오며 요청 본문이나 쿼리로 지정할 수 없다. 활성 계정인지 확인하고, DB 조회 조건에 작성자 ID와 삭제 여부를 포함한다. 타인의 문의와 없는 문의는 같은 404 응답으로 처리한다. 응답에 `Cache-Control: no-store`를 적용한다.

팀장·부팀장 등 팀 역할은 문의 권한에 영향을 주지 않는다. 현재는 작성자 전용 API만 제공하며 전체 문의 조회, 답변, 상태 변경, 수정·삭제 API는 없다. 프런트엔드의 로그아웃·계정 변경 시 문의 내용과 작성 중인 입력 상태를 제거한다.

## DB 적용

신규 DB에는 `be/src/main/resources/schema.sql`의 `inquiries` 테이블을 사용한다. 기존 DB에는 `be/src/main/resources/change_schema.sql` 끝의 **inquiries 테이블 생성 구문만 한 번** 적용한 뒤 새 백엔드를 배포한다. 전체 변경 이력 파일을 다시 실행하지 않는다.

## 추후 서비스 운영자 답변 기능

- 팀 역할과 독립적인 서비스 운영자 인증·권한 체계를 먼저 정의한다.
- 운영자 전용 목록·상세·답변 API는 별도로 추가하고 모든 요청에서 운영자 권한을 검증한다.
- 답변 본문·답변자·답변 시각의 저장 구조를 추가한다. 답변 저장과 `ANSWERED` 전환을 같은 트랜잭션에서 처리한다.
- 작성자 상세에 답변을 표시하는 기능을 함께 추가한다. 현재 UI는 문의 내용과 상태만 표시한다.
- 이번 버전에서는 답변 기능과 서비스 운영자용 조회 경로, 이메일·외부 알림을 구현하지 않는다.

## 검증 명령

- 프런트엔드: `cd fe`에서 `npm run lint`, `npm run build`.
- 백엔드: `cd be`에서 `./gradlew test --tests '*InquiryServiceTest' --tests '*InquiryControllerTest'`.
- 수동 확인: 로그아웃 상태, 계정 변경, 빈 목록, 등록 오류 시 입력 유지, 다른 작성자의 문의 ID 접근, 모바일·데스크톱 표시, 21건 이상 페이지 이동.
