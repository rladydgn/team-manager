# 페이지 접근과 404 처리

- 팀 목록·팀 홈·가이드는 공개한다. 공개 팀 상세 API는 비로그인·비팀원에게 팀원 목록을 반환하지 않는다.
- 경기 일정·팀원·통계·순위·경기 상세는 활성 팀원만 접근한다.
- 회비·팀 수정·가입 승인·시즌 설정·경기 생성 및 기록 관리는 팀장·부팀장만 접근한다.
- 문의·프로필은 로그인 사용자만 접근한다. 문의 상세의 작성자 검증은 서버에서 수행하며 팀 권한과 무관하다.
- 메뉴는 권한에 따라 숨기고, 직접 URL 접근은 공통 `PageAccessBoundary`에서 확인 후 본문을 표시한다. 경로나 로그인 계정이 바뀌면 확인 상태와 본문을 초기화한다.
- 접근할 수 없거나 존재하지 않는 페이지는 공통 404 화면을 표시한다. API의 403·404는 동일한 404 응답으로 처리한다.
- API 인증 실패의 401은 access 쿠키 자동 갱신에 필요하므로 유지한다. 한 번의 갱신·재시도 후에도 실패하면 화면에서 404로 처리한다. 로그인·회원가입 자체의 입력 오류는 이 처리에 포함하지 않는다.
- 클라이언트에서 권한 확인 후 표시하는 404 화면은 이미 전송된 페이지 문서의 HTTP 상태를 변경하지 않는다. 백엔드의 리소스 접근 거절 응답은 HTTP 404다.
- 네트워크·서버 장애는 404로 취급하지 않고 오류와 재시도 화면을 유지한다.

새로운 보호 페이지를 추가할 때 `fe/src/features/auth/model/page-access.ts` 정책과 서버 서비스의 권한 검사를 함께 추가한다. UI 검사는 서버 권한 검사를 대체하지 않는다.

검증: `fe`에서 `npm test`, `npm run lint`, `npm run build`. 서버 회귀 테스트는 `TeamVisibilityTest`, `AccessErrorResponseTest`를 포함한다.
